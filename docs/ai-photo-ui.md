# AI-фото в Silver: что сделать в экране (app.js)

Сервер и база уже готовы (функция `photo_ai`, версия от 20.11.2026). Нейросеть — Grok (xAI), ключ уже вписан.
Стили и правила — из документа «Стили генерации фото украшений — критерии». Здесь — только то, что нужно сделать в интерфейсе.
Старый блок «✨ AI-фото для сайта (Grok)» в карточке товара продолжает работать как есть (кнопки «белый фон» = стиль `catalog`, «на модели» = `tryon`), но его надо доработать по пунктам ниже.

## 1. Что есть на сервере

Все вызовы: `sb.functions.invoke('photo_ai', { body:{ action, ... } })`. Доступ: owner, manager, purchaser.

| action | Что передать | Что вернёт |
| --- | --- | --- |
| `styles` | — | `styles[]`: code, title, purpose, aspect, item_share, card_slot (1–3 = место в карточке, null = соцсети) |
| `analyze` | `product_id` или `order_item_id`; фото: `image` (dataURL) или `image_url`; без фото при `order_item_id` берётся фото поставщика из заказа | `analysis` (тип, металл, камни, детали, `card` = предложенные категория/материал/цвет), `suggested.styles[]` (code + why, 3–4 шт.), `suggested.palette`, `type_ru` |
| `gen` | `product_id` или `order_item_id`, `style`, фото (как в analyze), `n` (1–4, по умолчанию 2), `wish`, `size`, `refs[]` (до 3 https-ссылок на референсы бренда) | `photos[]` {id, url, status, check_result}, `passed`, `attempts`, `cost_usd`, `note` |
| `check` | `photo_id` + фото НАСТОЯЩЕГО изделия (`image`) | `pass`, `check` — перепроверка черновика по фото поставщика при приёмке |
| `review` | `photo_id`, `decision`: `approve` / `reject`; `make_main:true` — сделать главным фото товара; `force:true` — одобрить отбракованное вручную | `status` |

Ответ `gen` идёт до ~2 минут (генерация + проверка + до 3 перегенераций брака). Показывать «рисуем и проверяем… до 2 минут».

## 2. Статусы фото (`product_ai_photos.status`)

- `draft` — прошло автопроверку, ждёт одобрения менеджера.
- `supplier_draft` — сделано по фото поставщика (Китай), прошло проверку против фото поставщика. **Одобрить нельзя**, пока не сделана `check` по фото настоящего изделия.
- `approved` — одобрено человеком, можно на сайт.
- `rejected` — брак (автопроверка или человек). Причины: `check_result.reasons`, по пунктам: `check_result.items`.

## 3. Что сделать в карточке товара («Номенклатура»)

1. После загрузки фото — сразу `analyze`. Показать: «Распознано: Кольцо · серебристый · 2 прозрачных фианита-сердца» и **3–4 кнопки предложенных стилей** с подписью `why`. Остальные стили — в «Ещё стили».
2. Если в карточке пусто, а `analysis.card` что-то предлагает (категория, материал, цвет) — кнопка «Подставить в карточку».
3. Выбор стиля → `gen` (n=2). Пока ждём — заблокировать кнопку.
4. Результаты: **оригинал и результат рядом**. Под каждым — статус-чип и чек-лист из `check_result.items` (зелёные/красные пункты, `note`).
5. Кнопки: «Одобрить», «В брак», «Сделать главным». Для `rejected` — «Одобрить всё равно» только с подтверждением «Я сверил изделие сам» (`force:true`).
6. Список фото по умолчанию **без брака**; брак — под переключателем «Показать брак».
7. Главным фото товара может стать только `approved` — сейчас кнопка «Сделать главным» ставит фото напрямую; заменить на `review` с `make_main:true`.
8. Поле «Референсы бренда» (необязательно): ссылки на 1–3 фото, свет и настроение которых переносятся. Позже — сохранить их как пресет бренда.

## 4. Что сделать в заказах из Китая

1. У позиции заказа кнопка «✨ Черновик фото» → `gen` с `order_item_id` без фото, стиль по умолчанию `catalog`. Фото поставщика сервер берёт сам.
2. Сотрудникам источник подписывать **«Китай»**, не 1688.
3. При приёмке, когда позицию связали с товаром, черновики сами переходят к товару (триггер в базе).
4. В приёмке у товара с `supplier_draft`: «📷 Сфотографировать изделие и проверить» → `check`. Прошло — черновик становится `draft`, не прошло — `rejected` с причинами.

## 5. Стоимость (замер 20.11.2026, кольцо, стиль «Каталог», 2K)

- Генерация: ~$0.085 за вариант.
- Проверка совпадения: ~$0.013–0.021 за вариант.
- Распознавание: ~$0.002.
- Итого ~$0.10 за прошедший проверку кадр; с перегенерацией брака — до ~$0.30.
Писать стоимость рядом с кнопкой генерации: `cost_usd` из ответа.

## 6. Таблицы

- `photo_styles` — стили (меняет только владелец). Поля: code, title, purpose, method (`strict` для каталога и продуктовой, `redraw` для остальных), aspect, item_share, prompt, card_slot, sort, active.
- `product_ai_photos` — добавлены: style, status, source (`shop`/`supplier`), source_url, order_item_id, check_result, attempts, cost_usd, reviewed_by, reviewed_at. `product_id` теперь может быть пустым (черновик по позиции заказа).
- `product_ai_analysis` — результаты распознавания.
